# 小邮书接口设计文档

## 1. 文档说明

本文档用于说明“小邮书”项目前后端接口约定。前端根据本文档调用接口，后端根据本文档实现接口并返回统一格式的数据。

本文档中的接口字段采用前端常用的驼峰命名方式，例如 `createdAt`、`coverImage`、`likesCount`。数据库字段采用下划线命名方式，例如 `created_at`、`image_url`、`like_count`。后端负责完成数据库字段到接口字段的转换。

---

## 2. 接口通用规范

### 2.1 基础路径

开发环境接口基础路径：

```text
http://localhost:5000/api
```

### 2.2 请求数据格式

除图片上传等特殊接口外，所有接口默认使用 JSON 格式传递数据。

```http
Content-Type: application/json
```

需要登录的接口，请求头需要携带：

```http
Authorization: Bearer <token>
```

### 2.3 统一响应格式

后端所有接口统一返回如下 JSON 格式：

```json
{
  "code": 0,
  "message": "success",
  "data": {}
}
```

字段说明：

| 字段      | 类型                    | 说明                    |
| ------- | --------------------- | --------------------- |
| code    | number                | 业务状态码，0 表示成功，非 0 表示失败 |
| message | string                | 返回提示信息                |
| data    | object / array / null | 实际业务数据                |

### 2.4 常用返回状态约定

| 场景    | code | status_code | message |
| ----- | ---: | ----------: | ------- |
| 成功    |    0 |         200 | success |
| 参数错误  |  400 |         400 | 参数错误    |
| 未登录   |  401 |         401 | 请先登录    |
| 无权限   |  403 |         403 | 无权限操作   |
| 资源不存在 |  404 |         404 | 资源不存在   |
| 服务器错误 |  500 |         500 | 服务器内部错误 |

后端统一响应函数如下：

```python
from flask import jsonify

def success(data=None, message="success", code=0):
    return jsonify({
        "code": code,
        "message": message,
        "data": data
    })

def fail(message="error", code=400, data=None, status_code=400):
    response = jsonify({
        "code": code,
        "message": message,
        "data": data
    })
    response.status_code = status_code
    return response
```

## 3. 字段映射说明

接口字段不要求和数据库字段完全同名。后端需要在接口层完成字段转换。

| 接口字段            | 数据库来源                                     | 说明                       |
| --------------- | ----------------------------------------- | ------------------------ |
| `id`            | `posts.id` / `users.id` / `comments.id`   | 对应数据主键                   |
| `username`      | `users.student_no`                        | 学号                       |
| `nickname`      | `users.nickname`                          | 用户昵称                     |
| `avatar`        | `users.avatar_url`                        | 用户头像                     |
| `role`          | `users.role`                              | 用户角色                     |
| `title`         | `posts.title`                             | 帖子标题                     |
| `content`       | `posts.content`                           | 帖子正文                     |
| `summary`       | `posts.content`                           | 后端截取正文前 100 字生成          |
| `coverImage`    | `post_images.image_url`                   | 取排序第一张图片                 |
| `images`        | `post_images.image_url`                   | 当前帖子全部图片 URL             |
| `category`      | `categories.name`                         | 分类名称                     |
| `contentType`   | `posts.content_type`                      | 内容类型                     |
| `createdAt`     | `posts.published_at` / `posts.created_at` | 发布时间，优先使用 `published_at` |
| `likesCount`    | `posts.like_count`                        | 帖子点赞数                    |
| `collectsCount` | `posts.favorite_count`                    | 帖子收藏数                    |
| `commentsCount` | `posts.comment_count`                     | 帖子评论数                    |
| `isLiked`       | `post_likes`                              | 当前用户是否存在点赞记录             |
| `isCollected`   | `post_favorites`                          | 当前用户是否存在收藏记录             |
| `comments`      | `comments` + `users`                      | 评论列表及评论用户信息              |

# 4. 帖子模块

## 4.1 获取帖子列表

### 基本信息

| 项目     | 内容           |
| ------ | ------------ |
| 接口名称   | 获取帖子列表       |
| 请求方式   | GET          |
| 请求路径   | `/api/posts` |
| 是否需要登录 | 否            |

### 请求参数

| 参数       | 类型     | 必填 | 说明                              |
| -------- | ------ | -- | ------------------------------- |
| category | string | 否  | 分类名称，如“组队”“失物招领”“学习交流”等，不传则返回全部 |
| page     | number | 否  | 页码，默认 1                         |
| pageSize | number | 否  | 每页条数，默认 10                      |

### 后端处理说明

后端查询 `posts` 表中状态为 `PUBLISHED` 的帖子，并关联查询 `users`、`categories`、`post_images` 等表。

其中：

* `summary` 由 `posts.content` 截取前 100 字生成。
* `coverImage` 取 `post_images` 中该帖子 `sort_order` 最小的一张图片，没有图片则为 `null`。
* `author.avatar` 对应数据库中的 `users.avatar_url`。
* `likesCount` 对应 `posts.like_count`。
* `collectsCount` 对应 `posts.favorite_count`。
* `commentsCount` 对应 `posts.comment_count`。
* 未登录时，`isLiked` 和 `isCollected` 固定返回 `false`。
* 已登录时，后端根据当前用户是否在 `post_likes`、`post_favorites` 中存在对应记录返回布尔值。

### 成功响应示例

```json
{
  "code": 0,

          "id": 1,
          "nickname": "用户昵称",

        },
        "category": "学习交流",
        "contentType": "SHARE",
        "createdAt": "2026-06-08 12:00:00",
        "likesCount": 0,
        "collectsCount": 0,
        "commentsCount": 0,
        "isLiked": false,
        "isCollected": false
      }
    ],
    "total": 1
  }
}
```

## 4.3 发布帖子

### 基本信息

| 项目     | 内容           |
| ------ | ------------ |
| 接口名称   | 发布帖子         |
| 请求方式   | POST         |
| 请求路径   | `/api/posts` |
| 是否需要登录 | 是            |

### 请求参数

| 参数       | 类型     | 必填 | 说明                                   |
| -------- | ------ | -- | ------------------------------------ |
| title    | string | 是  | 帖子标题                                 |
| content  | string | 是  | 帖子正文                                 |
| category | string | 是  | 分类名称，对应 `categories.name`            |
| images   | array  | 否  | 图片 URL 数组，对应 `post_images.image_url` |

### 请求示例

```json
{
  "title": "帖子标题",
  "content": "帖子正文",
  "category": "学习交流",
  "images": [
    "https://example.com/image1.jpg"
  ]
}
```

### 后端处理说明

前端传入的是分类名称 `category`，数据库 `posts` 表实际保存的是 `category_id`。因此后端需要先根据 `categories.name` 查询分类 ID，再将分类 ID 写入 `posts.category_id`。

后端写入规则如下：

| 前端字段      | 数据库写入位置                                            |
| --------- | -------------------------------------------------- |
| title     | `posts.title`                                      |
| content   | `posts.content`                                    |
| category  | 查询 `categories.id` 后写入 `posts.category_id`         |
| images    | 批量写入 `post_images.image_url`                       |
| 当前登录用户 ID | `posts.user_id`                                    |
| 内容类型      | `posts.content_type`，后端默认设置为 `IMAGE_TEXT` 或 `TEXT` |
| 帖子状态      | `posts.status`，默认设置为 `PENDING_REVIEW`              |

如果 `images` 为空或未传，后端可将 `content_type` 设置为 `TEXT`；如果存在图片，后端可将 `content_type` 设置为 `IMAGE_TEXT`。

由于数据库设计中帖子需要审核，发布成功后默认进入 `PENDING_REVIEW` 状态。前端收到发布成功响应后，可以提示用户“发布成功，等待审核”。

### 成功响应示例

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "id": 1
  }
}
```

### 失败响应示例

```json
{
  "code": 400,
  "message": "分类不存在",
  "data": null
}
```

# 5. 用户模块

## 5.1 用户登录

### 基本信息

| 项目     | 内容                |
| ------ | ----------------- |
| 接口名称   | 用户登录              |
| 请求方式   | POST              |
| 请求路径   | `/api/user/login` |
| 是否需要登录 | 否                 |

### 请求参数

| 参数       | 类型     | 必填 | 说明                       |
| -------- | ------ | -- | ------------------------ |
| username | string | 是  | 学号，对应 `users.student_no` |

### 请求示例

```json
{
  "username": "2024000000",
```

### 成功响应示例

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "token": "登录凭证",
    "user": {
      "id": 1,
      "username": "2024000000",
      "nickname": "用户昵称",
      "avatar": "https://example.com/avatar.jpg",
      "role": "USER"
    }
  }
}
```

### 失败响应示例

```json
{
  "code": 400,
  "message": "学号或密码错误",
  "data": null
}
```

## 5.3 获取用户信息

### 基本信息

| 项目     | 内容                  |
| ------ | ------------------- |
| 接口名称   | 获取用户信息              |
| 请求方式   | GET                 |
| 请求路径   | `/api/user/profile` |
| 是否需要登录 | 是                   |

### 后端处理说明

后端根据 token 解析出当前登录用户 ID，然后查询 `users` 表及相关统计数据。

其中：

* `username` 对应 `users.student_no`。
* `avatar` 对应 `users.avatar_url`。

* `likesCount` 可统计该用户所有帖子获得的点赞总数。
* `collectsCount` 可统计该用户收藏的帖子数量。

```json
    "nickname": "用户昵称",
    "avatar": "https://example.com/avatar.jpg",
    "role": "USER",
    "stats": {
      "postsCount": 0,
      "likesCount": 0,
      "collectsCount": 0,
      "commentsCount": 0
    }
  }
```

# 7. 点赞与收藏模块

## 7.1 点赞或取消点赞

### 基本信息

| 项目     | 内容                    |
| ------ | --------------------- |
| 接口名称   | 点赞或取消点赞               |
| 请求方式   | POST                  |
| 请求路径   | `/api/posts/:id/like` |
| 是否需要登录 | 是                     |

### 路径参数

| 参数 | 类型     | 必填 | 说明    |
| -- | ------ | -- | ----- |
| id | number | 是  | 帖子 ID |

### 请求参数

无请求体参数。前端调用一次表示点赞，再调用一次表示取消点赞。

### 后端处理说明

后端根据当前用户 ID 和帖子 ID 查询 `post_likes` 表：

* 如果不存在记录，则新增点赞记录，并将 `posts.like_count` 加 1。
* 如果已存在记录，则删除点赞记录，并将 `posts.like_count` 减 1。

### 成功响应示例

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "isLiked": true,
    "likesCount": 1
  }
}
```

取消点赞后的响应示例：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "isLiked": false,
    "likesCount": 0
  }
}
```

# 8. 举报模块

## 8.1 提交举报

### 基本信息

| 项目     | 内容             |
| ------ | -------------- |
| 接口名称   | 提交举报           |
| 请求方式   | POST           |
| 请求路径   | `/api/reports` |
| 是否需要登录 | 是              |

### 请求参数

| 参数           | 类型     | 必填 | 说明                                            |
| ------------ | ------ | -- | --------------------------------------------- |
| targetType   | string | 是  | 举报对象类型，可选值：`POST`、`COMMENT`                   |
| targetId     | number | 是  | 被举报对象 ID                                      |
| reasonType   | string | 是  | 举报原因类型，例如 `SPAM`、`FALSE_INFO`、`ABUSE`、`OTHER` |
| reasonDetail | string | 否  | 举报补充说明，由前端输入框传入                               |

### 请求示例

```json
{
  "targetType": "POST",
  "targetId": 1,
  "reasonType": "FALSE_INFO",
  "reasonDetail": "内容不实或存在违规信息"
}
```

### 后端处理说明

前端提交举报时，需要同时传入举报原因类型 `reasonType` 和举报补充说明 `reasonDetail`。

数据库 `reports` 表中包含 `reason_type` 和 `reason_detail` 两个字段。后端写入时按以下规则处理：

| 前端字段         | 数据库写入位置                 | 写入规则                  |
| ------------ | ----------------------- | --------------------- |
| 当前登录用户 ID    | `reports.reporter_id`   | 从 token 中解析           |
| targetType   | `reports.target_type`   | 写入 `POST` 或 `COMMENT` |
| targetId     | `reports.target_id`     | 写入被举报对象 ID            |
| reasonType   | `reports.reason_type`   | 写入前端传入的举报原因类型         |
| reasonDetail | `reports.reason_detail` | 写入前端传入的举报补充说明         |
| 无            | `reports.status`        | 后端默认写入 `PENDING`      |

后端需要先校验请求参数和举报对象是否合法：

* 当 `targetType = "POST"` 时，后端检查对应帖子是否存在。
* 当 `targetType = "COMMENT"` 时，后端检查对应评论是否存在。
* 如果 `targetType` 不是 `POST` 或 `COMMENT`，返回 `400`。
* 如果 `targetId` 为空或格式不正确，返回 `400`。
* 如果举报对象不存在，返回 `404`。
* 如果 `reasonType` 为空，返回 `400`。
* 如果 `reasonDetail` 为空，可以写入 `null` 或空字符串。

### 成功响应示例

```json
{
  "code": 0,
  "message": "success",
  "data": null
}
```

### 失败响应示例

举报原因类型为空：

```json
{
  "code": 400,
  "message": "举报原因类型不能为空",
  "data": null
}
```

举报对象不存在：

```json
{
  "code": 404,
  "message": "资源不存在",
  "data": null
}
```

未登录：

```json
{
  "code": 401,
  "message": "请先登录",
  "data": null
}
```

# 9. 接口实现对应文件建议

后端可以按模块组织接口文件：

```text
xiaoyoushu-backend/
├── app/
│   ├── routes/
│   │   ├── user.py
│   │   ├── post.py
│   │   ├── comment.py
│   │   └── report.py
│   ├── utils/
│   │   └── response.py
│   ├── models/
│   │   ├── user.py
│   │   ├── category.py
│   │   ├── post.py
│   │   ├── post_image.py
│   │   ├── comment.py
│   │   ├── post_like.py
│   │   ├── post_favorite.py
│   │   └── report.py
│   └── __init__.py
```

接口文档与后端文件对应关系如下：

| 接口模块   | 后端路由文件                                         | 主要涉及数据表                                    |
| ------ | ---------------------------------------------- | ------------------------------------------ |
| 用户模块   | `app/routes/user.py`                           | `users`                                    |
| 帖子模块   | `app/routes/post.py`                           | `posts`、`categories`、`post_images`、`users` |
| 评论模块   | `app/routes/comment.py` 或 `app/routes/post.py` | `comments`、`posts`、`users`                 |
| 点赞收藏模块 | `app/routes/post.py`                           | `post_likes`、`post_favorites`、`posts`      |
| 举报模块   | `app/routes/report.py`                         | `reports`、`posts`、`comments`               |

# 10. 后端实现注意事项

1. 接口返回必须统一使用 `success()` 和 `fail()`，保证前端始终接收 `code`、`message`、`data` 三个字段。

2. 前端使用 `username` 表示学号，后端数据库中对应字段为 `users.student_no`。

3. 前端使用 `avatar` 表示头像，后端数据库中对应字段为 `users.avatar_url`。

4. 前端传入 `category` 分类名称，后端需要查询 `categories.name` 得到 `categories.id`，再写入 `posts.category_id`。

5. 前端传入 `images` 图片 URL 数组，后端需要逐条写入 `post_images` 表。

6. 帖子发布后默认状态为 `PENDING_REVIEW`，审核通过后才进入 `PUBLISHED` 状态。

7. 评论发布后默认状态为 `PENDING_REVIEW`，审核通过后才进入 `PUBLISHED` 状态。

8. 前端传 `reasonType` 和 `reasonDetail`，后端分别写入 `reports.reason_type` 和 `reports.reason_detail`。

9. 点赞和收藏接口采用切换逻辑：没有记录则新增，有记录则删除。

10. 未登录用户访问列表和详情接口时，`isLiked` 和 `isCollected` 返回 `false`。
